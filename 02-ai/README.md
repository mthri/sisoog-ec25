# دستیار صوتی فارسی

این پوشه یک دستیار صوتی برای مکالمه از طریق میکروفون و بلندگو دارد. تشخیص گفتار با Shenava و Silero VAD، تولید پاسخ با Ollama و تبدیل متن به صدا با Pocket TTS انجام می‌شود. در اجرای فعلی، STT و TTS روی CPU راه‌اندازی می‌شوند؛ دستگاه اجرای LLM را Ollama مدیریت می‌کند.

## فایل‌ها و کاربردشان

| فایل یا پوشه | کاربرد |
| --- | --- |
| [`main.py`](main.py) | نقطهٔ شروع برنامه و کلاس `VoiceAssistant`؛ آماده‌سازی مدل‌ها و مدیریت چرخهٔ شنیدن، پاسخ‌گویی و پخش صدا. |
| [`stt.py`](stt.py) | کلاس `ShenavaASR` برای تبدیل گفتار فارسی به متن و استفاده از Silero VAD برای تشخیص شروع و پایان صحبت. تنظیمات در `ASRConfig` قرار دارند. |
| [`tts.py`](tts.py) | کلاس `PocketTTS` برای تولید صدا، نرمال‌سازی متن فارسی، تقسیم متن، ذخیرهٔ WAV و پخش صوت با صف و ترد تولید جدا. تنظیمات در `PocketTTSConfig` با نام جایگزین `TTSConfig` قرار دارند. |
| [`llm.py`](llm.py) | ارتباط با Ollama، پرامپت سیستم و مدیریت گفتگو با `ChatManager` یا نام جایگزین آن، `ChatSession`. شامل پاسخ کامل (`ask`)، پاسخ متنی استریم (`ask_stream`) و آماده‌سازی مدل (`warmup_llm`) است. |
| [`models.py`](models.py) | مدل‌های `Conversation` و `Message` و عملیات SQLite با Peewee؛ ساخت، بازیابی و حذف گفتگو و ذخیرهٔ پیام‌ها. |
| [`requirements.txt`](requirements.txt) | وابستگی‌های اصلی پروژه با نسخهٔ مشخص؛ زیر‌وابستگی‌ها هنگام نصب خودکار دریافت می‌شوند. |
| `pocket-tts/` | فایل‌های دانلودشدهٔ مدل TTS، تنظیمات `farsi.yaml`، توکنایزر و صدای مرجع. |
| `shenava-koochik/` | فایل‌های دانلودشدهٔ مدل تشخیص گفتار، از جمله `shenava-koochik-1.0.nemo`. |
| `conversations.db` | پایگاه دادهٔ گفتگوها؛ به‌صورت خودکار ساخته می‌شود. |
| `.venv/` و `__pycache__/` | محیط مجازی پایتون و کش اجرای پایتون؛ بخشی از منطق دستیار نیستند. |

## نصب و آماده‌سازی

دستورهای زیر برای محیط Bash نوشته شده‌اند. به پایتون سازگار با وابستگی‌ها، میکروفون، خروجی صدا و Ollama نیاز دارید. دانلود اولیهٔ مدل‌ها و بسته‌ها به اینترنت نیاز دارد.

### ۱. ساخت محیط پایتون

از ریشهٔ مخزن وارد پوشه شوید:

```bash
cd 02-ai
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

نصب کامل وابستگی‌ها ممکن است چند گیگابایت دانلود داشته باشد و نسخه‌های ثبت‌شده باید با پایتون و سیستم‌عامل شما سازگار باشند.

فایل `requirements.txt` فقط وابستگی‌های مستقیم کد و ابزار دانلود مدل را نگه می‌دارد. گزینهٔ `nemo-toolkit[asr]` وابستگی‌های تشخیص گفتار را هم نصب می‌کند؛ نیازی به فهرست‌کردن جداگانهٔ زیر‌وابستگی‌ها نیست.

### ۲. دانلود مدل تبدیل متن به صدا

مدل مورد استفاده: [Pocket TTS فارسی](https://huggingface.co/mehdi-hf/pocket-tts-farsi).

داخل پوشهٔ `02-ai` اجرا کنید:

```bash
hf download mehdi-hf/pocket-tts-farsi --local-dir pocket-tts
```

**بعد از دانلود، فایل `pocket-tts/farsi.yaml` را باز کنید و مقدار دو کلید زیر را تغییر دهید:**

- کلید `weights_path` در سطح اصلی فایل: `model.safetensors`
- کلید `tokenizer_path` داخل `flow_lm` و سپس `lookup_table`: `tokenizer.model`

محل قرارگیری این مقادیر به این شکل است؛ این نمونه فقط بخش مرتبط را نشان می‌دهد و نباید جایگزین کل فایل شود:

```yaml
weights_path: model.safetensors

flow_lm:
  # سایر تنظیمات این بخش را حفظ کنید.
  lookup_table:
    # سایر تنظیمات این بخش را حفظ کنید.
    tokenizer_path: tokenizer.model
```

تورفتگی YAML و تمام تنظیمات دیگر را حفظ کنید. `tokenizer_path` را به سطح اصلی فایل منتقل نکنید.

فایل‌های زیر باید داخل `pocket-tts/` موجود باشند:

```text
pocket-tts/
├── farsi.yaml
├── model.safetensors
├── tokenizer.model
├── example_voice.wav
└── normalize_fa.py
```

سه فایل اول برای بارگذاری مدل لازم‌اند. `example_voice.wav` صدای مرجع پیش‌فرض است و مسیر آن با `voice_path` در `PocketTTSConfig` تغییر می‌کند. در صورت نبود `normalize_fa.py`، کد از نرمال‌سازی ساده‌تر داخلی استفاده می‌کند.

#### پاسخ‌گویی با صدای خودتان

برای اینکه دستیار پاسخ‌ها را با صدایی شبیه صدای شما تولید کند، یک نمونه از صدای خودتان
ضبط کنید و آن را جایگزین فایل `02-ai/pocket-tts/example_voice.wav` کنید.
نام فایل را دقیقاً `example_voice.wav` نگه دارید و برنامه را دوباره اجرا کنید؛
نیازی به تغییر کد نیست.

شرایط نمونهٔ صوتی:

- **مدت ۲ تا ۵ ثانیه:** یک جملهٔ کوتاه فارسی را کامل و با لحن طبیعی بخوانید. ابتدای کلمات و انتهای جمله بریده نشود. در تنظیمات فعلی، از فایل‌های طولانی‌تر فقط ۵ ثانیهٔ اول استفاده می‌شود.
- **قالب WAV با PCM شانزده‌بیتی:** ترجیحاً تک‌کاناله (مونو) و با نرخ نمونه‌برداری ۲۴ کیلوهرتز ذخیره کنید. تغییر پسوند یک فایل MP3 به `.wav` کافی نیست؛ آن را واقعاً به WAV تبدیل کنید.
- **فقط یک گوینده:** موسیقی، صدای تلویزیون یا صحبت افراد دیگر در فایل نباشد.
- **ضبط تمیز و واضح:** در محیط ساکت، بدون پژواک محسوس و با فاصلهٔ ثابت از میکروفون ضبط کنید. صدا خیلی ضعیف یا آن‌قدر بلند نباشد که خش‌دار و خراب شود.
- **گفتار معمولی:** آرام و شمرده صحبت کنید؛ از آواز، نجوا، فریاد و سکوت طولانی در ابتدا یا انتهای فایل پرهیز کنید.

این فایل نمونهٔ صدای گوینده است؛ لازم نیست متن پاسخ‌های دستیار را در آن بخوانید.
شباهت خروجی به صدای شما به کیفیت ضبط و توانایی مدل بستگی دارد و دقیقاً یکسان بودن
صدا تضمین نمی‌شود. توصیهٔ نمونهٔ کوتاه و تمیز در [راهنمای صدای مرجع مدل](https://huggingface.co/mehdi-hf/pocket-tts-farsi#voice-prompts) هم آمده است.

### ۳. دانلود مدل تبدیل گفتار به متن

مدل مورد استفاده: [Shenava Koochik](https://huggingface.co/Reza2kn/Shenava-Koochik-v1.0).

```bash
hf download Reza2kn/Shenava-Koochik-v1.0 --local-dir shenava-koochik
```

مسیر مورد انتظار برنامه:

```text
shenava-koochik/shenava-koochik-1.0.nemo
```

### ۴. آماده‌سازی Ollama

Ollama را مطابق [راهنمای رسمی](https://docs.ollama.com/quickstart) نصب و سرویس آن را اجرا کنید. اگر سرویس از قبل فعال نیست، در ترمینال جدا اجرا کنید:

```bash
ollama serve
```

نام مدل تنظیم‌شده در `llm.py` برابر `gemma4:e2b` است. آن را در محیط Ollama آماده کنید:

```bash
ollama pull gemma4:e2b
```

اگر از مدل دیگری استفاده می‌کنید، `MODEL_NAME` در `llm.py` را مطابق نام مدل نصب‌شده تغییر دهید. آدرس پیش‌فرض API در کد `http://localhost:11434/v1` است و از طریق `BASE_URL` تغییر می‌کند.

## اجرای دستیار

در پوشهٔ `02-ai` و با محیط مجازی فعال:

```bash
python main.py
```

پس از نمایش پیام `All models ready` صحبت کنید. برای توقف `Ctrl+C` بزنید.

چرخهٔ برنامه:

1. مدل STT و VAD، سپس مدل TTS بارگذاری می‌شوند و یک درخواست کوتاه برای آماده‌سازی LLM ارسال می‌شود. اگر آماده‌سازی LLM خطا بدهد، برنامه پیش از فعال‌کردن میکروفون متوقف می‌شود.
2. `listen_utterance` میکروفون را باز می‌کند و بدون محدودیت زمانی برای شروع صحبت منتظر می‌ماند.
3. پس از حدود ۸۰۰ میلی‌ثانیه سکوت یا رسیدن صحبت به سقف ۲۰ ثانیه، میکروفون بسته می‌شود و صوت ضبط‌شده به متن تبدیل می‌شود.
4. متن غیرخالی با `ChatSession.ask` به LLM ارسال می‌شود. برنامه منتظر پاسخ کامل متنی می‌ماند.
5. پاسخ به جمله‌ها تقسیم می‌شود. یک ترد جدا صوت را تولید و بررسی می‌کند و ترد اصلی تکه‌های آماده را به‌ترتیب پخش می‌کند.
6. بعد از پایان پخش، میکروفون دوباره فعال می‌شود و نوبت بعدی آغاز می‌شود.

### استریم و صف صوتی

در حین پخش جملهٔ فعلی، ترد تولید می‌تواند جمله‌های بعدی را آماده کند. صف حداکثر **۱۰ تکهٔ صوتی** را در حافظه نگه می‌دارد؛ یک جمله ممکن است چند تکه داشته باشد. این صف یک بافر موقت است و فایل کش دائمی ایجاد نمی‌کند.

تولید صوت روی یک ترد انجام می‌شود؛ چند ترد هم‌زمان مدل TTS را اجرا نمی‌کنند. `synthesize_stream` هر بخش کوتاه متن را با `generate_audio` تولید و سپس تحویل می‌دهد، بنابراین استریم در سطح تکه‌های متن است. اگر سرعت تولید از پخش کمتر باشد، ممکن است بین تکه‌ها مکث ایجاد شود.

`ask_stream` در `llm.py` موجود است، اما مسیر فعلی `main.py` از آن استفاده نمی‌کند؛ استریم فعلی مربوط به تولید و پخش صداست. میکروفون در تمام مدت پردازش پاسخ و پخش بسته می‌ماند و قطع پاسخ با صحبت‌کردن پشتیبانی نمی‌شود.

ورودی‌هایی که فقط علامت نگارشی، فاصله یا ایموجی دارند به مدل TTS فرستاده نمی‌شوند؛
مثلاً `...` بعد از جداکردن جمله‌ها نباید درخواست تولید صدای جداگانه بسازد.
اندازهٔ پیش‌فرض تکه‌ها ۱۸ توکن است تا مطابق [راهنمای مدل](https://huggingface.co/mehdi-hf/pocket-tts-farsi)
احتمال تولید تکراری در متن‌های طولانی کمتر شود. صدای مرجع فقط برای تعیین ویژگی‌های
گوینده استفاده می‌شود و در مسیر پخش مستقیم یا جایگزین پاسخ قرار ندارد.

با این حال، خود مدل گاهی محتوای صدای مرجع را به‌جای متن ورودی بازتولید می‌کند.
در `main.py`، صوت تولیدشده پیش از پخش با همان STT بارگذاری‌شده رونویسی می‌شود؛
میکروفون در این مرحله بسته است. اگر شباهت متن تشخیص‌داده‌شده به متن درخواست، پس از
نرمال‌سازی و حذف فاصله و علائم، کمتر از ۰٫۵ باشد، تکه دوباره تولید می‌شود.
پس از سه تلاش ناموفق، خطا گزارش می‌شود و آن تکه وارد صف پخش نمی‌شود.
این بررسی تقریبی است، کمی تأخیر اضافه می‌کند و ممکن است به‌علت خطای STT هم باعث
تلاش مجدد شود. فراخوانی مستقل `PocketTTS` بدون `audio_validator` این بررسی را ندارد.

## تنظیمات کاربردی

| محل تنظیم | پارامتر | مقدار یا کاربرد فعلی |
| --- | --- | --- |
| `llm.py` | `SYSTEM_PROMPT` | لحن فارسی خودمانی و پاسخ کوتاه، مناسب مکالمهٔ صوتی. |
| `llm.py` | `MODEL_NAME` / `BASE_URL` | نام مدل و آدرس API سرویس Ollama. |

| `main.py`، فراخوانی `listen_utterance` | `phrase_time_limit` | مقدار پیش‌فرض ۲۰ ثانیه؛ برای تغییر آن، آرگومان را به فراخوانی اضافه کنید. |

| `tts.py`، `PocketTTSConfig` | `temperature` | مقدار ۰٫۳ برای تولید صدا. |
| `tts.py`، `PocketTTSConfig` | `chunk_pause_seconds` / `join_seconds` | هر دو ۰٫۱۵ ثانیه؛ فاصله بین بخش‌های تولیدشده در یک فراخوانی سنتز. |

صدای ورودی با نرخ ۱۶ کیلوهرتز و خروجی با نرخ ۲۴ کیلوهرتز پردازش می‌شود. انتخاب دستگاه صوتی در کد فعلی به دستگاه پیش‌فرض `sounddevice` وابسته است.

## تاریخچهٔ گفتگو

`models.py` هنگام import اتصال SQLite و جدول‌ها را آماده می‌کند. مسیر پیش‌فرض `conversations.db` نسبت به پوشه‌ای است که برنامه را از آن اجرا می‌کنید؛ با اجرای دستورهای بالا، فایل در `02-ai` ساخته می‌شود. اگر ماژول `config.py` با مقدار `DB_PATH` تعریف کنید، از آن مسیر استفاده می‌شود.

هر اجرای `main.py` یک گفتگوی جدید می‌سازد. پیام‌های همان جلسه به‌عنوان تاریخچه به LLM فرستاده می‌شوند. گفتگوهای قبلی در پایگاه داده باقی می‌مانند، ولی ادامهٔ خودکار آخرین گفتگو در `main.py` پیاده‌سازی نشده است. برای بارگذاری یک جلسه در کد می‌توان از `ChatManager.load(conversation_id)` استفاده کرد.

## اجرای مستقل بخش‌ها

این دستورها را از داخل `02-ai` اجرا کنید:

| دستور | رفتار |
| --- | --- |
| `python stt.py` | شنیدن پیوسته از میکروفون و چاپ متن تشخیص‌داده‌شده؛ بدون LLM و TTS. |
| `python tts.py` | تولید صدای متن نمونه، ذخیره در `output_pocket.wav` و سپس تولید و پخش دوبارهٔ همان متن. |
| `python llm.py` | ارسال پیام‌های نمونه به LLM، نمایش پاسخ کامل و استریم، و ذخیره در پایگاه داده. |
| `python models.py` | ایجاد یک گفتگوی آزمایشی و پیام‌های نمونه در پایگاه داده و چاپ تاریخچه. |

برای دیدن دستگاه‌های صوتی قابل دسترس:

```bash
python -m sounddevice
```

اگر مدل یا صدای مرجع پیدا نشد، مسیرها و فایل‌های دانلودشده را بررسی کنید. اگر آماده‌سازی LLM شکست خورد، فعال‌بودن Ollama، نام مدل و `BASE_URL` را بررسی کنید. برای خطاهای ورودی/خروجی صدا، دستگاه پیش‌فرض سیستم و دسترسی میکروفون را بررسی کنید.
